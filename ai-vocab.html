Part 1: The Setup

Where AI lives, runs, and presents itself
01

Model

The brain. The actual AI doing the thinking.

The same brain can show up in lots of different places — when you use Claude inside Cursor, that's the same Claude that's on claude.ai.

Examples
Claude (Opus, Sonnet, Haiku) GPT (4, 5) Gemini Llama DeepSeek
You might also hear
LLM large language model foundation model "the AI" frontier model
02

App

The way you talk to the brain.

The product wrapped around the model. Different apps are designed for different jobs — chatting in a browser, coding in your terminal, drafting in a doc — but the brain inside is often the same.

Examples
Claude.ai Claude Code Cowork ChatGPT Cursor GitHub Copilot Lovable, v0
You might also hear
client interface product surface harness wrapper IDE
03

Environment

Where it runs and what it can reach.

The same model in a different environment has wildly different powers. You don't usually pick the environment directly — you pick the app, and the environment comes with it.

Analogy: A doctor at a coffee shop vs. a doctor in a hospital are the same doctor — but only one can perform surgery because of the building and tools surrounding them.
Examples
Cloud only (ChatGPT, Claude.ai) Cloud sandbox + connected folders (Cowork) Your laptop, full access (Claude Code, Cursor)
You might also hear
sandbox runtime host workspace local vs. cloud container

Part 2: The Operating Concepts

Every AI workflow is a combination of these four
01

Instructions

What you want it to do.

Anything you write down once so you don't have to say it every time. Save rules somewhere the AI can read if you plan to do a workflow repeatedly.

Examples
Saved "weekly update" prompt CLAUDE.md file in a project Custom GPT's instructions Claude Code skill
You might also hear
skill prompt system prompt custom instructions persona CLAUDE.md .cursorrules
02

Tools

Actions it takes on your behalf.

Anything the AI does instead of just talking. Searching the web, writing files, reading calendars, sending emails, or running code.

Examples
Web search Read/write files Read calendar Send email Run code
You might also hear
function calls tool use actions capabilities computer use browser use
03

Connections

Where info comes from & goes.

The other apps you want the AI to access — inbox, calendar, Drive, Slack, Notion. Connections let the AI read/write on your behalf.

Examples
Gmail & Calendar Drive, Dropbox, Notion Slack GitHub Folder on your Mac
You might also hear
integration connector MCP / MCP server API plugin data source
04

Triggers

How it gets kicked off.

Something has to start the AI. Beyond typing, you can fire prompts on a schedule or when events happen in other applications.

Examples
You typing in chat Slash command (/weekly-brief) Daily 9am schedule Email arriving Push to GitHub
You might also hear
schedule cron / cron job automation routine webhook

Why Does This Matter?

Cutting through the noise of new terms

Part of why AI feels so noisy is that new words keep emerging to describe different combinations of these building blocks. If you understand the core blocks, you can ignore the noise.

Case Study: OpenClaw vs. Standard Assistants

Always-on Environment

Runs on standalone hardware or cloud servers — continues working even when your laptop is closed.

Sandboxed Safety

Walled-off execution. The AI can run free within its sandbox without risking sensitive files elsewhere.

Mobile & Automated Triggers

Uses "heartbeats" (e.g. checking every 30 mins) or mobile messages (WhatsApp) to kick off async tasks.

Adaptive Tooling

If blocked (e.g. OpenTable blocking bots), it can write code to invoke voice APIs and call via phone.

Notice the progression: The further right you go, the more the AI can do — but the more setup, trust, and system access you grant.

Understanding Ecosystem Incentives

Model Provider Incentives: Vendors prefer lock-in. If your skills, memories, and connectors live inside proprietary platforms like Cowork, switching models means rebuilding. If they live as plain files on your laptop (like CLAUDE.md in Claude Code), you remain model-agnostic.

Enterprise Incentives: Companies seek to mitigate risk, protect PII, and prevent data loss. These reasonable goals naturally push toward cloud-hosted, sandboxed, opt-in environments with controlled tool access.
